# Changelog

## 0.3.0

### Changed

- The request layer and the command table are code generated by [cloudflare/forge](https://github.com/cloudflare/forge). Commands, options, output, and exit codes are the same as in 0.2.1.
- Of the query parameters on the configured URL, only `thread_id` is sent with each message. 0.2.1 passed every parameter through.
- Library: `Wording.uploadLimitHelp` takes the default per-file limit as its second argument.

## 0.2.0

### Added

- `dwh check` verifies the configuration and the destination with one GET request; nothing is posted.
- `dwh send` is the explicit spelling of the default command. `dwh -- check` sends a file named `check`.
- `--dry-run` resolves every input as a real run would and prints the plan; nothing is sent.
- `--json` prints one JSON object on stdout: per-file name, size, message id, attachment id, and URL, the message count, and the duration. On failure it carries the diagnostics and the files delivered before the failure.
- `-q, --quiet` prints nothing but errors; a `--json` result is still printed.
- `dwh --help` lists the commands and global options; `dwh send --help` and `dwh check --help` give each command's options, examples, and behavior.
- `DWH_HIDE_DESTINATION=1` keeps every output (help, progress notes, errors, `--json`, `check`) to "the user" and "the destination". Webhook URLs become `<destination>`, also in text from the network, and `--json` leaves out attachment URLs.
- Usage errors, missing files, directories, devices, oversized files, and failed downloads end with `help:` and a command to copy (`ls -la`, `zip -r`, `split -b 9M`, `curl -sSI`, ...). Running `dwh` with piped stdin but no `-` says to add `-`.
- Hints for Discord error codes: 40005 and 413 name the largest file; 10015, 50027, 401, 403, and 404 point at the configuration; 10003 points at a stale `thread_id`; 50035 suggests a plain filename.
- Library: `run`, `checkWebhook`, `resolveWebhookConfig`, `isWebhookUrl`, `DiagnosticError`, `formatDiagnostic`, `scrubDiagnostic`, `diagnosticsOf`, `wordingFor`, `hideDestinationFrom`, and `neutralize`. `sendFiles` returns a `SendResult` with one `Delivery` per file (message id, attachment id, URL). Diagnostics reach callers scrubbed, and `sendFiles` and `checkWebhook` throw `invalid-config` for a URL that is not a Discord webhook URL.
- A webhook URL given as an input is refused instead of downloaded, since that would post the webhook object, token included, into the channel. So is an input that redirects to one. Percent-encoded spellings of the path are recognized, and redacted in canonical form.
- A file that exists but cannot be read (mode 000, an I/O error) is reported as `unreadable`, with a hint to check its permissions.

### Changed

- stderr carries one line per diagnostic: `{location}: {severity} dwh({code}): {message} help: {remediation}`. The location is the input (a path, a URL, or `stdin`) or `dwh`, the severity is `error` or `advice`, and the code is stable. In 0.1.1 lines read `dwh: <message>` and could span several lines.
- Library: `onNote(string)` is now `onDiagnostic(Diagnostic)`, and `onSent(file)` is now `onSent(file, delivery)`. Every thrown error is a `DiagnosticError` whose `message` is the formatted lines. `OutgoingFile` has an optional `source`.
- Messages use plain ASCII punctuation.
